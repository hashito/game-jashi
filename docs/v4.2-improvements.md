# 邪視 v4.2 — 戸の向こうにも、山は動いている

今回の目的は、突然置かれる怪異ではなく、見ていない間も動いている山を作ること。探索対象の分かりやすさを維持しつつ、戸を閉める・音の止まる瞬間を待つ・小物の細部を調べる選択を増やす。

## 依頼と改修

| 依頼 | 改修内容 |
| --- | --- |
| 最初の邪視が突然現れる | 覗く前から同じ白い影が遠くを歩く。望遠鏡の三段階で表示を切り替えず、歩行・位置・向きを引き継ぎ、最後は首から身体へ振り向く。追跡開始も観察終了時の座標を使う。 |
| 看板が大きく邪魔 | 幅0.8〜1.35m、高さ0.34mの道標へ縮小。通行線から離し、視線より低い位置に置く。 |
| ドアと部屋設計 | 別荘玄関・物置・避難小屋・一階寝室・二階納戸に開閉可能な引戸。前壁・間仕切り・棚・ベンチを設置。二階のベランダは既存の雨戸を使用。階段、調査位置、退出路は衝突を伴う実経路で検査する。 |
| 深い霧と不要なマップの読み込み削減 | 通常の霧密度を0.034から0.060へ。地面、幹、枝、針葉、草、落葉を区画化し、近い範囲だけ描画資源を生成。通常は38mで生成、46mを越えて離れると解放。望遠鏡は対象までの通路を先読みし、光学用の霧0.021を使う。 |
| 怖い音 | 戸の軋み・ラッチ、間隔の異なるノック、遠い擦れ、低い息と音が途切れる間を追加。既存の音量・消音・停止・会話抑制を守り、建物の音は実座標から鳴らす。 |
| アイテムの写真 | 長靴・作業日誌・手鏡の接写を3点追加。ゲーム内の3D見本と一緒に記録画面へ表示。写真内の細かな文字に依存せず、調査内容は読みやすい本文で示す。 |
| ギミック | 戸を閉めると移動・視線を遮る。怪異は記憶した行き先へ進む途中の戸を三度叩き、4.4秒で開ける。戸口にいる人を挟まない。小物5点に任意の追加調査ボタンを設け、発見した細部を保存する。 |
| 細かな怖い情報 | 靴底と裸足の跡の違い、白紙に残る筆圧、手鏡の裏の紙、録音末尾の時刻、作業札の空欄を追加。必須ルートや生還条件に余分な収集を要求しない。 |

## 操作と状態

- 戸を見ると「開ける／閉める」を表示。PCはE、タッチは「調べる」。閉じると視線を切れるが、怪異の予備動作から逃れる時間を作る使い方になる。
- AIの経路計画は戸を開ける前提で組めるが、実際の移動・視線・攻撃は閉じた戸を通らない。叩く対象は現在のプレイヤー位置を盗み見せず、AIが実際に計画した次の地点から選ぶ。
- 記録画面の追加調査は時間を止めて読める。既存の記録からも確認でき、同じ細部を調べ直してイベントを増やさない。
- v3/v4の記録を引き続き受け付ける。新しい項目は初期値へ補完。新設の壁に重なる古い記録は近い同階の空間へ移し、戸の途中で保存した場合は復帰位置の戸を開ける。

## 描画資源と素材

衝突・道・進行情報は軽い共通データとして常駐する。遠くの描画用ジオメトリとインスタンスバッファを未生成／解放にするため、非表示にするだけの方式ではない。共有テクスチャは解放対象に含めない。通常移動は1更新4区画まで、開始・望遠鏡・長距離の復帰は表示前に先読みする。CPU互換描画の地面は1区画18三角形を基本とし、道の下へ描く。

実ワールドの開始地点では装飾インスタンス3,766/7,184（47.6%減）、地面31/144区画（78.5%減）。CPU互換描画の地面は558三角形で、以前の簡略地面1,568三角形から64.4%減る。これは資源数の比較であり、フレームレートの保証ではない。全域の歩ける地点を4m間隔で調べた最大要求は176区画で、上限192区画以内。望遠鏡の対象まで地面・森が途切れないことも検査する。

新しい写真3点は組み込みimage_genで並行生成し、選定後に720×540のWebPへ圧縮した。合計141,328バイト。プロンプトと出力は `tools/photo-briefs-v4.2.json`、出典・元画像と納品物のSHA-256は `tools/local-media-records/*-v4-2.json`、共通素材台帳は `assets/production.json` に保存。完成済み写真の再生成を避け、共通 `media-queue.json` では検証ジョブをCPUプールで並行実行する。D:/AIの既存GPUジョブやサーバー設定は変更しない。音はゲームのWeb Audio合成を改修した。

## 4分割生成と山中の掲示物

追加の掲示物4点・記録写真4点は、1枚に4点を含む2×2シートを2枚だけ生成する方式に変更。独立した2シートを並行生成し、中央で四等分し、512pxのWebPへ変換する。今回の配信画像は各512×512px、8点合計385,722バイト。生成回数は8点を個別に作る場合の8回から2回となる。生成サービスの実課金額や生成時間が必ず4分の1になるとは扱わない。

正本は `tools/scene-art-briefs-v4.2.json`。四隅の対応、プロンプト、納品先を生成前に固定する。`tools/prepare-scene-art.py SHEET_ID SOURCE.png` は元画像のコピーと切り出しのみを行い、元画像のハッシュ・寸法・切り出し矩形を各素材の記録へ残す。境界の混入がある場合だけ `--seam-trim 2` で内側の境界を削る。画像を伸ばして整える処理はしない。`node tools/verify-scene-art.mjs --require-source` で元シートも検査し、CIでは配信用画像と追跡可能な記録を検査する。

絵は山道、林業の物置、避難小屋、橋に置く掲示物と、別荘、伐採現場、橋の足跡、駐車車両の記録写真。日本語の見出しは描画コードで重ね、生成文字に依存しない。小さな壁面掲示や額に収め、通行路を塞がない。調べると写真と不穏な説明を拡大し、読んでいる間は探索時間を止める。必須アイテムの取得条件や結末には追加収集を要求しない。

掲示画像は14m以内で読み込み、19mより離れると描画用テクスチャを解放する。読み込み途中で離れた場合も後着のテクスチャを破棄する。共通キューは掲示・写真・怪異材質の3シート分の完成素材を並列検証した後、26素材の台帳を再構築する。

## 怪異の材質と画像容量

怪異の肌・古布・鎌の鉄・柄の木を1枚の2×2シートから制作。384px WebPの4点、合計137,486バイトを身体と道具に貼る。縦の一つ目、無毛の輪郭、遠景での視認性を保ち、取得に失敗しても基底色のモデルを表示する。

写真14点は1,674,504から833,606バイトへ約50%軽量化。既存の地面・樹皮・木板・枝・タイトル・肖像・顔画像・小物見本の計23点は2,265,686から383,286バイトへ83.1%削減した。小物16点は可逆WebPで画素を維持し、枝の透明度も維持する。原本を保持し、未使用の旧画像は配信ビルドから除外する。台帳は `assets/runtime-images.json`、再処理は `tools/optimize-runtime-images.py`。

再利用できる怪異4点と森林4点はgame-kitの共有カタログにも登録する。各ゲームが選択した素材だけを同期でき、ゲーム固有の写真や物語は共通素材に含めない。

## 検証

`npm test`、`npm run check`、`npm run assets:release`、`npm run build` に加えて、`node tools/smoke-v42.mjs` で実画面の戸・探索・追加調査・望遠鏡・掲示物の拡大操作を確認する。追加8画像はブラウザーでもデコードする。既存の `npm run smoke` はPC／スマホ相当の探索案内と帰還までを検証。`node tools/check-audio-render.mjs` は音を実際のWeb Audioグラフで生成し、左右定位、ピーク、クリッピング、有限値を検査する。

自動検査は実機スマートフォンの性能や、人による怖さ・音の聴感評価を代替しない。写真は架空の証拠写真であり、実在事件の記録ではない。
