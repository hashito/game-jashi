# 4.1 探す物が伝わる探索

## 改修する体験

- 目標を「物の名前・見た目・置き場所・目的・操作」に分け、HUD、地図、探し物の詳細に同じ情報を使う。
- 物置の「箱」という存在しない目標を「蓋つきのボトル2本」に統一。書き置きと修司の案内も、西のボトル→東のハンドルの順にする。
- 見本は実際の3Dモデルの画像。未発見の怪談や任意の携帯は目標に混ぜない。
- 近くでは「同じ階か・遮られていないか・対象を向いているか」を確認して案内を変える。壁越しの強調はしない。
- 無線待ちは独立した状態にして、開けられないゲートへの矢印を消す。
- 探し物の詳しい説明は時間を止めて読める。字幕を増やさず、危険時には案内を縮める。
- 目標更新、見つけた時、鍵・ボトル・ハンドルの取得音を短く区別。怪異の足音を覆う連続誘導音は追加しない。
- 導入・帰還後の写真と山の古写真を更新し、写真の役割を説明と物語に分ける。

## 標準との接続

`kit.json` からgame-kitの `step-guide` を同期し、操作が停滞したときの追加ヒントに使う。
素材の準備・検収には共有 `media-queue` と `check-production-assets` を使う。画像生成の指示は先に記録し、生成済み原本を入力にしてキューで配信用ファイルを作る。生成ツールへの受付を完成と扱わない。

既存のMountainWorldには二階・坂・遮蔽・怪異の視線・Canvas2D描画・v3/v4のセーブ移行がある。今回はこれらを平面主体の標準雛形へ再生成せず、案内と制作・検証ツールを段階的に導入する。共通モジュールのコピーは直接編集しない。

## 検証

通常順序・先回り取得・保存復帰・無線待ち・任意記録を既存の実コントローラー試験に追加する。別階・遮蔽・対象を見ていない場合の案内、消音時と停止時の音も検査する。PC、スマホ縦横の実画面で写真、字幕、案内、操作ボタンの重なりを確認する。

## D:/AIを参考にした品質確認（2026-10-30）

「計画→生成受付→実ファイル確認→測定→修正→記録」の手順を採用。音声8本はD:/AIのVOICEVOXでCPU生成し、ピークを−6dBFS、クリップ0に揃えた。写真3点は組み込みimage_genで作成した原本を検収して採用。D:/AIのComfyUIはAPIが接続拒否で、追加調査では別系統のGPU版VOICEVOXのGPU使用も確認した。GPUリセットや他の制作ワーカーの停止は行っていない。生成方法の違いは素材ごとの台帳に残す。

探索・保存・音声を含む152テスト、PC1440×900・スマホ390×844／844×390の実ブラウザー操作で検査。初回検査で地図の上に説明が大きく出る問題を見つけ、地図上部は小さい見本と場所だけに変更した。同じ目的の古い保存へ戻った際のヒント遅延、音声を連打した際の状態上書き、操作継続中の誤った開始案内も修正して回帰テストを追加した。

Web Audioの新しい効果音5種は実グラフから書き出し、有限サンプル・有音・ピーク0.98未満を検査する。UI確認はブラウザーの画面サイズとタッチ入力のエミュレーションであり、実機スマートフォンでの触感や人間による聴感評価とは区別する。PRでも同じ自動検査を継続実行し、画面写真と音声の測定値を成果物に残す。

LinuxのCIではマウス固定が有効になり、HUDのクリックだけでは案内を開けない問題を検出した。PCはHキーで開けるようにし、HUD・操作説明にも表示。smokeもPCは実キー、タッチ端末は実クリックで操作する。CIの日本語フォント不足も補い、文字を読める画面写真を残す。

CPUによるWebGL描画ではゲーム内4.2秒の車始動が実時間30秒を超え、タイムアウト直後の失敗画面には正常な帰還画面が記録されていた。CIの脱出待ち上限を90秒へ延長した。車を実際に操作して帰還写真まで到達するという合格条件、ゲームの進行速度、他の検査は変更していない。
